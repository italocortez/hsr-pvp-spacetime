## Goal

Make abuse expensive for the attacker instead of relying on the energy cap (A16, A41): bound and throttle the fan-out reducers, cap per-user storage, give guests a kill switch that trips itself, and leave a count-only alert row the external notifier can read.

## Findings and deviations

1. **Orchestrator correction to its own brief:** the brief told the implementer to clear `AbuseBreakerJob` in `server_nuke_test_data`; that would stop the breaker on test1 until the next wipe. Reverted by the orchestrator: the chain survives the nuke like `IdentityGcJob` / `LobbyGcJob`; docs corrected.
2. **Throttle stamps rewrite `LobbyMember`.** Every accepted cursor event (up to 20 Hz per player) deletes and re-inserts the member row to stamp `lastCursorAt` (§B.5 design: the stamp lives on the private row, no audit bump). Egress consequence for S9: **member views must not project `lastCursorAt` / `lastLineupAt`**, or every subscriber receives a member-row update at cursor rate. Recorded on the S9 roadmap row.
3. **Chat minimum interval** has no column of its own: `send_chat_message` already materializes the lobby's messages for the 50-row cap, so the sender's newest message is found in that array at no extra read. If a moderator deletes that message the sender may skip one interval. Accepted.
4. **Breaker cost:** `Lobby` has no `createdDate` index, so each run is one `AbuseConfig` read plus a full `Lobby` scan (live lobbies only) and one `User.id.find` per lobby inside the window; once tripped, one read. Idle cost ≈ 8,640 reducer calls/month, negligible against the cursor traffic in `tools/energy-model.js` but not zero. **Alternative not implemented (A42 says scheduled):** evaluate the burst inline in `create_lobby` for guests, zero idle cost and an instant trip; the user decides whether to amend A42.
5. **No chat exemption** for moderators or admins: the chat contract has none, so none was added (CLAUDE.md §3).
6. **Harness gotchas (S10):** `LobbyCursorEvent` rows are visible only inside the transaction that inserted them (event table), so the cursor tests count rows inside each call; reading `test.db` inside a `withReducerTx` body crashes the in-memory datastore ("unreachable").
7. Biome formatting not applied (lint gate is M3).
