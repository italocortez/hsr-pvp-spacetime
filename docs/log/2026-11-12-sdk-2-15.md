# SDK and CLI upgrade to SpacetimeDB 2.15.0 (2026-11-12)

## Goal

Upgrade from 2.14.1 to 2.15.0 before the frontend steps (user request, A165).

## Decisions implemented

- **A165**: `spacetimedb` pinned to exactly 2.15.0; CLI 2.15.0 is the default (2.14.1 stays installed).

## Files changed

- `spacetimedb/package.json`, `package-lock.json` (the `spacetimedb` entry only; no transitive change).
- `web/src/module_bindings/index.ts` (+8 / −202): version stamp; the generated `DbView` alias type is gone, the SDK now carries the deprecation marks of the old accessor names onto `conn.db`. No schema, table, view or reducer change.
- `scripts/stdb/_seed.ts`: five uses of deprecated accessor names renamed (`conn.db.Archetype` to `conn.db.archetype`, `conn.db.Achievement` to `conn.db.achievement`).
- Docs: `README.md`, `docs/FRONTEND-HANDOFF.md`, `CLAUDE.md` (two version mentions), the `spacetimedb` skill (present-tense version statements, a "2.15.0 for this repo" paragraph, a corrected line on `clear()`), a comment in `shared/stdb-targets.ts`.

## Schema changes

None.

## Done check

- `npm run typecheck`: 0 errors. `spacetime build --module-path spacetimedb`: passes. `npm run stdb:generate`: one binding file.
- `npm test`: unit 21 files **432 passed**; in-memory 108 files **2157 passed / 1 skipped / 15 todo / 0 failed**. No maincloud contact.
- The three publish dry-runs print valid commands; `--help` of `publish`, `generate`, `describe`, `login show`, `sql`, `logs` and `build` is identical between 2.14.1 and 2.15.0.

## Findings and hand-offs

- Nothing in module code or tests needed a fix. The `clear()` fix of 2.15 lives in the host and the module never uses the returned count. The in-memory test kit API, `senderAuth.isInternal` and views with arguments are unchanged.
- `test/shared/connection.ts:103` still uses the deprecated accessor `view_my_identity` (works; the rename to `viewMyIdentity` needs a test task).
- The table option `scheduled:` on three job tables was already deprecated; moving off it is a refactor, left.
- The 2.15 Auth package (`@spacetimedb/auth` 0.1.0) could host the OAuth flow inside the module; it brings its own user and session tables, a signing key stored in the database and four dependencies. Not adopted (A46 stands).
- test1 still runs the module built with 2.14.1 until the next publish (user gate). After that publish: watch the first publish output for prompts, re-run the live suite once.
- Deviations from a decision row: the SDK version pinned in MIGRATION-PLAN is superseded by A165.
