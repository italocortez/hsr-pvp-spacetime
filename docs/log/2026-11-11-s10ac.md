# S10ac — the calendar backend follows the calendar mockup (2026-11-11)

## Goal

The user asked for a review of the calendar against the design (`notes/audit-2026-11-09/calendar-review.md`), accepted its recommendations and removed recurrence. This step implements them.

## Decisions implemented

- **A157**, 12 points: slot kind Available / Blocked with the overlap refusal; 10 slots per UTC week; recurrence removed; a time change resets answers; the attendee list for invitees of personal events; busy blocks for savers; guests and users pending deletion refused as targets; an invitee may leave; past starts refused; a weekly sweep of old rows; one validator for time arguments with length and distance bounds; avatars, the one-call invitee edit and the match time in the bracket.

## Files changed

- Module: `tables/calendar/availabilitySlot.ts`, `types` (`SlotKind` new; `RecurrenceRule`, `RecurrenceType` removed), `reducers/calendar/*`, new `helpers/calendar/calendarTargets.ts` and `calendarTime.ts`, `helpers/calendar/calendarCleanup.ts`, `views/calendarViews.ts`, `reducers/identity/identityGc.ts` (the sweep), the bracket schedule helper.
- Bindings: 8 files (three reducers, `types.ts`, four view tables).
- Tests: new `calendar/mockup-rules.test.ts` (50 tests), 6 new in `views/calendar-views.test.ts`; 6 recurrence tests removed (the user removed recurrence); re-aligned: `calendar/slots-and-events`, `event-caps`, `event-rules-and-cleanup`, `views/calendar-views`, `tournaments/reject-guest-entry`, `tournaments/verified-requirement`, fixtures `calendar.ts` and `views.ts`.
- Docs: `docs/calendar/architecture.md`, `docs/views/architecture.md`, `docs/tournament/architecture.md`, `docs/ERD.md`, the calendar and tournament contracts (markers and Phase History rows), `ROADMAP.md`.

## Schema changes

`availability_slot`: columns `isRecurring`, `recurrenceRule`, `expiresAt` dropped, `kind` added. Struct `RecurrenceRule` and enum `RecurrenceType` removed; enum `SlotKind` added. Reducer signatures changed: `create_availability_slot`, `update_availability_slot`, `update_calendar_event`. Reaches maincloud with the S11a clear publish.

## Review

Independent Fable 5.2 reviewer, read-only, own models, verdict **COMMIT AFTER FIXES** (`notes/audit-2026-11-09/s10ac-review.md`).

- Slots: 36,000 seeded random actions against a model of the weekly cap, 0 disagreements. Events: 10,800 actions with 22 kinds of viewer, 475,200 view reads, 0 disagreements; no leak to savers, outsiders or anonymous tournaments. Every reducer argument tried with bad values: no raw error.
- M1 (fixed): the invitee id list was parsed loosely; an id above u32 wrapped to a real user and stored a duplicate invite; a junk list on update removed every invitee. Now strict ("Invalid invitee list."); 10 tests.
- Open for the user (rule questions, not fixed here): M2 a slot that has ended frees its place in the weekly cap, so rows per user have no ceiling; M3 the attendee list multiplies the invite view for invitees; a team member who leaves a match event still sees it; a Blocked slot may be placed onto an existing event; guests are auto-invited to match events and cannot answer; retention clears the bracket's `scheduledAt`; self-invites and the SYSTEM user as target; UTC week against the viewer's local week.

The M1 fix was verified by the orchestrator's suite run.

## Findings and hand-offs

- `run_identity_gc` has no caller check in code; it relies on the engine refusing outside callers (verified on an older version). On the S11a list: verify live, then add the guard.
- Staff who did not create a match event cannot read it through the calendar views, though they may edit it; the tournament page reads match times from the bracket.
- A title of only invisible characters passes.
- `tools/energy-model.js` keeps a size constant for the removed `RecurrenceRule`.
- The mockup has no control for the removed recurrence; none is needed.
- Deviations from a decision row: none.
