## Reducer signatures after S7

- `record_group_scores(lobbyId, gameNumber, teamSide, values: u32[] hundredths, deaths: u8, screenshotUrl?)` — captain of that side or a referee; upserts one `MatchResultGroupScore` row per group index, deaths on the game row, recomputes the game, resets both confirmations; current game only.
- `set_score_adjustment(lobbyId, gameNumber, teamSide, value: i32 hundredths, reason?, adjustmentId?)` — referee, or organizer / Admin in a tournament lobby; no id inserts (0 rejected), id + value ≠ 0 edits, id + 0 deletes; resets confirmations.
- `arrange_lineup(lobbyId, teamSide, groups: JSON string[][])` — captain of that team or a referee; `lineupFormat` group count, 4 per group, every drafted character once; live `MatchLineup` row with surcharge and live roster cost, `isConfirmed` cleared; throttled (`lineupMinIntervalMs`, reject); no step logged.
- `confirm_lineup(lobbyId, teamSide)` — same callers; Auction rejected while surcharge > remaining light-cone budget; fixes `rosterCost`, logs `ConfirmLineup` with the groups.
- `submit_match_result(matchResultId, winnerOverride?, winnerOverrideReason?)` — referee or staff; recomputes the current game; every game needs complete scores; override only on a level-4 tie (A39 paths); series winner incl. the A27 head start; Casual finalizes inline.
- `pick_character` / `nominate_character`: unchanged arguments; under `requireOwnership` the eidolon is the max over the member's selected accounts and the argument is ignored.

## Findings and deviations

1. **The test fallout of an API removal needs its own task.** Removing `record_game_scores` and `winnerId` broke 4 lines in the S4 in-memory tests and 58 in the legacy live suites, all off-limits to the implementer. T-S7(c) ported the two S4 F8 tests with their assertions intact and patched the live suites compile-only (S10 rewrites them). Lesson for S8 (which deletes six legacy writers): plan the test task alongside the removal.
2. **Import convention.** `@shared/scoring` initially broke the unit runner because `test/vitest.config.ts` had no `@shared` alias (two unit suites import module helpers that now reach the scoring glue). The orchestrator added the alias, mirroring `tsconfig.base.json`, and the module imports the barrel like `@shared/lobby-rules`.
3. **Override audit survives finalization** (closed the implementer's own gap): `MatchSessionHistory` carries the three override columns, copied by `runFinalization`, asserted in the S7 test. The A21 todo requires it ("kept for audit and replay").
4. `teamSide` on `arrange_lineup` / `confirm_lineup` (a referee must name the team); optional `screenshotUrl` on `record_group_scores` (Ranked validation needs both screenshots); `groups` on `ConfirmLineupPayload`; `arrange_lineup` logs no step (fan-out).
5. **Current game only:** scores and adjustments are accepted for `MatchSession.currentGameNumber` only, because tie-breaks 2 and 3 read that game's steps and `advance_to_next_game` deletes them. Earlier games of a series keep the outcome computed while they were played; corrections go through staff tools.
6. **Series:** one `winnerOverride` decides every tied game; a tied game does not advance the series before submit.
7. **12-pick Classic order:** Thirds appends R-B-B-R-R-B-B-R to the 8-pick sequences (`notes/draft_order.md` defines only 8-pick orders; implementer's continuation of the snake). Auction: `isAuctionComplete` counts `charactersPerTeam(lineupFormat)`.
8. **Per-game loops** (`lobbyGameNumbers`) instead of prefix index scans: the 2.14.1 in-memory datastore rejects a bare-scalar prefix scan and returns nothing for prefix + `Range` (known caveat, ACCESS-SECURITY-OPS §D.5).
9. **Synergy pairs** stored alphabetically and matched in either order; re-submitting an existing pair updates it (upsert semantics); editor argument names unchanged.
10. `handicapApplied` = Blue's net handicap advantage minus Red's over the games; modifiers excluded.
11. `runFinalization` throws on a record without a winner (A31). **The Auction surcharge is checked at confirm but not debited from the light-cone budget**; see Review for the verdict.
12. "Seated" = any Blue/Red slot incl. coaches; "casual" = non-tournament.
13. Biome formatting not applied (lint gate is M3).
