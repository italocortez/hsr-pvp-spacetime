# S10ad — calendar rulings after the S10ac review (2026-11-11)

## Goal

Implement the user's rulings on the open questions of the S10ac review (A160) and of this step's own review (A161).

## Decisions implemented

- **A160**: 10 Available and 10 Blocked slots per week, ended slots counted; a Blocked slot is refused over an own event; Pending invites of ended events are removed; the bracket keeps a match time through retention; self and SYSTEM targets refused; a title needs a visible character. Unchanged by ruling: team members keep seeing their match event, guests keep their automatic match invite, the week is UTC.
- **A161**: the attendee list comes from `view_event_attendees(eventId)`, subscribed per opened event (a view cannot read the clock, so A160(5) could not be built); Pending invites go 7 days after the end; a bracket cascade clears the match time also when the event is gone.

## Review

Independent Fable 5.2 reviewer of the first pass, read-only, verdict **COMMIT AFTER FIXES** (`notes/audit-2026-11-09/s10ad-review.md`).

- Cap: 108,000 seeded random actions against an own model, 0 disagreements; at most 560 slot rows per user, the stated bound. Blocked-over-event refused on every route, no deadlock. Pending removal correct on the three paths. 40 titles in 12 scripts accepted, 27 blank ones refused.
- F1 (fixed): after retention kept a match time, a rollback, cancel or resolve no longer cleared it.
- F2 (ruled, A161(2)): an ended event moved to the future had lost its unanswered invitees; Pending invites now go 7 days after the end.
- F3 (ruled, A161(1)): A160(5) cannot be built in a view; the attendee view replaces it. A filtered subscription on the existing view is unproven on SDK 2.14.1 and was not used.

The fix pass (the attendee view, the 7 days, F1) was verified by the orchestrator's suite run and the implementer's mutation check (9 tests fail with the F1 fix and the 7-day rule broken); it was not independently reviewed.

## Findings and hand-offs

- Calendar page: subscribe own invites always; subscribe `view_event_attendees` only for the open event and drop it on close; tiles of events one is invited to show the organizer's avatar only; a past week can differ per invitee because unanswered invites disappear.
- `view_event_attendees` has no primary key (a view with an argument cannot have one): an answer arrives as a delete plus an insert.
- `cleanupEndedPendingInvites` reads every invite the caller holds on each calendar call; received invites have no cap per user (accepted).
- A few invisible characters still pass as a title (Braille blank, private-use). The description is not checked.
- `tools/energy-model.js` line for `availability_slot` still adds bytes for removed columns and lists the table as public.
- Deviations from a decision row: A160(5) not built, replaced by A161(1) with the user's agreement.
