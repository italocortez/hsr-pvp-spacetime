## Diagnostic (for the user to triage)

- **A113(2), the Disqualified exclusion** (`it.skip`, comment `DIAGNOSTIC S10q`): the row refuses the setting change "while guest enrolments exist"; the code skips Disqualified guest enrolments (`tournamentManagement.ts:309`), so a tournament whose only guest entry is disqualified accepts the change. Known since the S10m review (F5) as a deliberate deviation: counting them would block the organizer forever, since a disqualified row is permanent. Either the row gains an exception or the code changes.

## Pins of current behaviour where the decision is silent (for the user to rule)

1. A110: the only owner of a pick is deleted before the tournament completes, on a side of two: nobody is credited.
2. A110: an abandoned player who owns the character is credited.
3. A112: a guest that still has a second identity is not deleted at sign-in, so the entry stays with the guest.
4. A113(4): a seated guest with a second identity is not refused the sign-in.
5. A113(1): `minimumMmr` 0 is stored as no floor and forces nothing.
6. A115(4): rating rows written at the same instant list the higher id first.
7. A124: the scheduled identity GC deleting a guest organizer does not cancel the tournament; it keeps the deleted id as organizer.
8. A124: `server_link_provider` deleting a guest organizer does not cancel either.

Pins 7 and 8 need engineered state (a guest cannot organize a tournament).
