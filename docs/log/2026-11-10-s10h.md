# S10h — lobby and identity rulings: guests, cursor events, seat labels, away members, private lobbies (2026-11-10)

## Goal

Implement the user's lobby and identity rulings from the backend closing audit. Rows A100 to A102, A106 and A107 are left for S10i.

## Decisions implemented

- **A95**: the weekly identity clean-up deletes a guest idle for 30 days with no match history; guest creation is counted, and crossing the threshold pauses new guest creation and alerts the admins.
- **A96**: cursor events carry the seat (`senderJoinSeq`), never a user id or a label. The member restriction was not built (see below).
- **A97**: anonymous labels come from the seat kind and seat number.
- **A98**: away and abandoned members cannot act in the lobby.
- **A99**: a private lobby needs a password.

## Limits and formats chosen in this step

Guest retention 30 days idle, at most 500 guest deletions per run (next run one hour later when the cap is hit); guest creation threshold 100 per 10 minutes; label format "<seat kind> #<seat number>"; guest name "Guest_" plus the last 8 hex characters of the identity.

## Findings and hand-offs

- **Guest name collision (found by the test task, pre-existing):** every identity starts with the fixed tag `c200`, so "Guest_" plus the first 8 hex characters had 16 varying bits and guest login would have failed on the unique username after a few hundred guests. Fixed: last 8 characters, with a `_2`, `_3` fallback.
- **Open for the user (review F3): the guest creation breaker is a cheap lock-out.** As decided it pauses new guest creation until an admin acts. Because a Discord sign-in from a new browser starts as a guest, a trip also blocks new verified players and admins on a new device, and more than 100 first-time visitors in 10 minutes trips it without an attacker. Recommendation put to the user: a self-healing window with a default of 300. Not changed here.
- **Open for the user (A96):** the cursor event table stays public, carrying lobby id, seat number and position. Recommendation: accept.
- **`dispute_match_result` stays unguarded** by A98: a participant right on a record that names them; reported to the user.
- Staff still need a member row for `kick_member`, `ban_member` and `set_captain` (unchanged requirement); `set_captain` admits Admin only among staff (D-30).
- A private lobby switched to public loses its password, so going back to private needs a new one (A99 reading, reported to the user).
- Old position-based labels already stored in chat are shown for departed senders until the S11 clear-publish empties the table.
- The live residue was aligned but not run (first run at S11).
- Deviations from a decision row: none.
