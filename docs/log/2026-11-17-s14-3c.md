# S14.3c: the team builder's loadouts, account sync and share link (2026-11-17)

## Goal

Third sub-step of the team builder: saved loadouts on the page (a browser list for everyone, an account list for verified members through the S14.3s backend), automatic saving of account loadouts with the ring the user asked for, the note with its counter, the delete confirmation, "Copy to my account", the "Copy link" share button, the reworded intro and the footer. Test task T-S14.3c. No backend change, no change under `spacetimedb/`, `shared/teambuilder/`, `shared/scoring/` or `web/src/module_bindings/`, no dependency, nothing published or deployed.

## Decisions implemented

- **A190 item 1:** account storage for verified accounts only; guests and visitors use browser storage.
- **A190 item 2:** "Copy link" writes the team into the address (`team=`, the format the page already reads).
- **A190 item 3:** 5 loadouts in the browser, 10 on the account.
- **A190 item 10:** delete asks for confirmation in a dialog.
- **A190 item 15 (as amended by A194):** a loadout holds its team, modes, cost set, budgets and bids (the packed text), a name (40) and a note (1,000, visible counter); after sign-in both lists stay, with "Copy to my account" per browser loadout.
- **A194 items 3 to 6:** save 60 s after the last edit (restart on edit), a 5 minute ceiling, save on switch, leave and tab hide, every edit kept as a draft at once, no "save now" button, the ring that turns into a check reading "Auto saved", never more than 6 saves per minute; a refused save keeps the draft and retries.
- **A193 item 3:** the page never sends a blank name ("Untitled" on blur, as the mockup).

## Choices made where the brief asked (for the user to rule on)

| Question | Choice | Why |
|---|---|---|
| First loadout | The page starts with a working loadout (its team is the S14.3a draft); its first change (team, modes, name or note) makes it a loadout in the store that applies | nothing to click; no empty loadout is ever stored |
| Account slots | List in slot order; a new loadout takes the lowest free slot, counting loadouts not saved yet; `isNew` when no row and no save of this visit holds the slot | the server's key is the slot; no reorder in the mockup |
| Save confirmation | The reducer call's promise (resolves on commit, rejects with the text); the draft goes when the view's row matches | a save that changes nothing sends no row; the call tells which save failed and why |
| Drafts on load | Applied and sent; a conflict (server copy changed since) is said, with "Use the account copy" | a draft is the newest unsaved writing; a prompt on every reload would be noise |
| Two tabs | Read-change-write per loadout in storage, `storage` events reload the browser list; each tab its own scheduler; last writer wins; a row arriving is never an edit | no lost loadout, no save loop |
| Linked team | Opens as its own unsaved loadout ("Shared team"); Restore goes back to the loadout that was active | a link never overwrites a saved loadout |
| Browser loadouts instead of the ring | "Saved in this browser" with a check | nothing waits: every change is written at once |
| Delete on the last loadout | allowed (the mockup hides it); the team stays as the working loadout | nothing is lost and the button does not vanish |

- Answers and sends read the row from the connection's cache at that moment (the server sends a transaction's rows before the call's answer); the drafts are checked against the rows again after every answer.
