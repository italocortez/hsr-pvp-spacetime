## Findings and deviations

1. **Nested `@shared` paths do not bundle.** `@shared/stdb-targets` resolves, `@shared/lobby-rules/refereeTransfer` does not (same tsconfigs as M1). Each shared folder therefore exports a barrel (`shared/lobby-rules/index.ts`); S7 (`shared/scoring/`) and S8 (`shared/bracket/`) must do the same.
2. **F9 extended to every step writer.** Classic Pick/Ban/EMPTY inserts used `sequence: turnIndex`, so fixing only the Pause/Undo rows still collided (Pause(2) then Pick(2) after resume). All writers now use `getNextSequence`; sequences stay 0, 1, 2… until the first pause/undo, after which Classic `step.sequence` no longer equals the draft slot. `resume_draft` finds the Pause step by action tag (unaffected). **S9 views and the S14 lobbyroom must derive the draft slot from the order of Pick/Ban steps, not from `sequence`.** Undo's dead `isAuctionPhase` revert branch removed; `originalSequenceId` is the deleted step's sequence.
3. **Auto-pause payload** now writes the typed `timeRemainingMs` (pause_draft's formula); the old hook wrote a non-existent `accumulatedPauseMs` field hidden by `as any`. F10's pause math is untouched.
4. **NoAction policy.** The grace check is scheduled under every policy in an active stage, so the referee/captain/host flags can move after 15 s under NoAction too (the old hook skipped every transfer under NoAction). A22(5) and the prototype have no policy exception, `decideAutoPause` does (never a pause under NoAction); documented in `docs/lobby/contract.md`. Orchestrator judgment: a referee gone for 15 s needs replacing regardless of the pool policy.
5. **Captain/host transfers** in the check are gated on `ACTIVE_STAGES` (D.8.2's sketch had no gate; parity with the old hook). "Still offline" = `LobbyMember.isOnline` false **and** no live presence row.
6. **`claim_forfeit`:** 0 derives from the caller's slot, 1/2 name the team for anyone (the eligibility gate is unchanged), non-zero required for the exclusive referee, other values rejected.
7. **F1 restore** also flips `voluntarilyLeft` rows online; harmless: `isForfeitEligible` and every flag-candidate filter exclude `voluntarilyLeft`.
8. `approve_stand_in` inserts no `LobbyMember`, so no `joinSeq` there; the host gets 1, later joins max + 1.
9. `docs/lobby/architecture.md` also corrects `LobbyMember` to private (an S3 fact missed in S3's deliberate doc freeze).
10. B-8 is inert until S5 seeds `AbuseConfig` (id 1).
11. `isInternal` guards on `run_*` (MIGRATION-PLAN follow-up row) deliberately **not** added: the skill requires the live sensor re-check first → S11.
12. Biome formatting not applied (lint gate is M3).
13. **Two `MatchResultRecord` rows per lobby (pre-existing; found by T-S4).** `performConcede` (`concede.ts:29`) and `defer_match` insert a second record next to the Pending one from `start_draft`, so the guards' `[0]` read never saw a concede. A read-only Opus researcher traced the old repo's planning trail: phase 09 (2026-03-29, `8ef2543`) created the Pending record at `start_draft`; phase 10 (2026-04-03: `0070408` guard, `234c08e` inserts, `46cdc25` participant fallback) was written as if no record existed mid-draft ("need to create records mid-draft", `10-CONTEXT.md:323`); a 2026-04-10 debug session saw the pair and logged it as test residue; the migration review listed `performConcede` as clean and F8's proposed guard copied `[0]`. Casual lobbies hide it (inline finalization deletes both rows); tournament lobbies parked in AwaitingResult expose it in `admin_force_finalize` (`[0]` → finalizes the Pending row as a normal result), `process_tournament_mmr` (`[0]` by bracket match → may skip the Validated concede row) and the dispute guard. **S4:** `hasConcededRecord` scans every record (the T-S4 test passes). **S8 (A54):** one record per lobby, concede/defer update the Pending record, the three tournament readers read it explicitly, the D-75 participant fallback becomes the rule for concedes.
