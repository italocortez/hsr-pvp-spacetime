# S14.3e: a loadout is the characters picked; exact amounts on the page

Date: 2026-11-17. Branch: `main` (uncommitted; HEAD `257683a` at the start, tree clean).

## Goal

1. Implement DECISIONS.md A205: a loadout comes into being with its first character. Mode, cost set, budget, name and note changes on an empty unsaved working loadout store nothing; a stored loadout emptied of its characters stays.

3. Added during the step by the orchestrator (user question): on the exported picture, a paired unit's pill carries the page's link icon instead of the S14.3d gold edge.

## Choices made here

- **Where the empty working loadout's name and note live:** in the active key (`hsrpvp.teambuilder.active.v1`, `{ kind: 'working', name, note }`), written only when they differ from the defaults. Not in the team draft key: that key holds the packed team text read by S14.3a code; the active key already describes the working loadout (shared flag, the loadout a link replaced) and is never read as a list. Modes stay in the address, budgets in the team draft, as before.
- **State line:** "Pick a character to start a loadout." (quiet text, no ring). A full store and a loading account list keep their own lines first.
- **New Loadout:** saves the loadout being left at once and shows a fresh working loadout; it stores nothing itself, so presses never pile up empties; pressed on an empty working loadout it resets its name and note. Refusals unchanged.
- **Duplicate, Delete, Copy to my account:** row actions of the menu, so not offered for the working loadout; on a stored empty loadout they work as on any other. **Copy link:** stays enabled on an empty team (harmless: the link opens an empty shared team that stores nothing).
- **Pairs strip:** "+1.5" and "+3" as before; two decimals only when the modifier has hundredths.
- **Picture icon in jsdom:** without `Path2D` the painter leaves the icon out, so the page-level picture tests (which stub the canvas) are unchanged; the layout tests cover the icon.
