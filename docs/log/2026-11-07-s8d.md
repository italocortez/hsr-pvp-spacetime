## Goal

Close the tournament rewrite: tournament lobbies created from a bracket match with the preset's free set and the tournament's integrity set, seats enforced through `allowedSlotsFor`; one `MatchResultRecord` per lobby; the settled result handed to the bracket through the single writer with the lobby parked in AwaitingResult; finalization of every tournament match in a scheduled job at Completed or Cancelled; the S7b hand-offs (`unequip_lightcone`, draft check, latest-Pause auto-resume); and A65: `MatchSessionStep` rows kept for the whole series, Admin edits reaching earlier games.

## Rules as implemented

- **Tournament lobby**: caller = member or approved stand-in of either team, or `bracket` staff; match Ready, tournament InProgress, no live lobby for the match (`Lobby.bracket_match_id`); 14 integrity columns from the tournament (bestOf from the bracket match), free set from the preset → system preset row → `SYSTEM_PRESET_VALUES`; `bestOfNAdvantage` Blue iff `winnerAdvantage > 0`; creator host + referee: a participant is auto-seated on its team, staff sits as a spectator referee and becomes a member (one lobby at a time applies). Stand-ins: any verified non-guest user not enrolled on the other team, `teamId` stored. `join_lobby` auto-seats (Waiting only); `set_team_slot` enforces `allowedSlotsFor`; `shuffle_teams` rejected (A35); `reclaim_referee` also for seated staff with `canResolveResults` (D.8.4).
- **One record per lobby**: `start_draft` is the only inserter; concede and defer update the Pending record (status, `matchEndReason`, trigger, summary, stage, `settledAt`, `refereeUserId`) and reject when none exists (every caller runs after `start_draft`); `findLobbyResult` behind every former `[0]` read.
- **Hand-off**: `handOffToBracket` from `submitSeriesResult` (Casual, at the deciding close), `validate_match_result` (Submitted or Disputed → Validated, `results` permission) and `performConcede`; `applyBracketResult` idempotent, Blue = `team1Id`, Red = `team2Id`, `seriesGames(session)`; the lobby parks in AwaitingResult; no finalization before the tournament ends; `finalize_match_result`, `admin_void_match`, `admin_force_finalize` reject tournament lobbies with the D.8.3 pointer.
- **Staff corrections**: rollback → record Voided (row kept), lobby hard-deleted (`keepResultRecord`); resolve keeps a parked Validated record for the same winner, every other lobby of the match voided; `override_match_result` on tournament records = rollback + re-apply, accepts Submitted / Disputed / Validated only and rejects when the lobby is gone; a Rejected override rolls back, voids the lobby and keeps the status.
- **Completed / Cancelled**: format check + `canComplete`, no live lobby outside AwaitingResult; placements ("1224": elimination = champion 1, final loser 2, third-place winner then loser, then by knockout round with Losers rounds above Winners rounds; GroupOnly by group position, equal positions share; GroupInto* elimination teams first; Withdrawn / Disqualified unplaced; Walkover finals count); `finalizationStartedAt`; one job row scheduled now. Cancelled keeps bracket, teams, members and assistants (review §5.1 "kept for display"), voids every lobby except parked Validated ones, counts stats, skips MMR.
- **Job tick**: reschedule first; the first 4 surviving records in bracket order (groups, Winners, Losers, third place, grand final; round, then match); Validated → `runFinalization(…, { tournamentMmr })` with MMR inside step 11 (real `MmrHistory` id, sentinel back-fill gone) only when `countTowardsMmr` and Completed; other records deleted without effect; at the end one leaderboard rebuild (Completed MMR tournaments only), `finalizedAt`, job rows deleted; the nuke clears the table. A throwing tick rolls back its own reschedule row: `admin_restart_tournament_finalize` (Moderator+; terminal stage, `finalizedAt` unset, no job row) re-inserts the job at cursor 0, which is correct because every processed record is deleted.
- **A65**: `advance_to_next_game` keeps the steps; `currentGameSteps` feeds the 11 game-scoped readers; `getNextSequence`, the user-deletion guard, the GC and the finalization read stay lobby-wide (sequences keep increasing across the series); finalization archives every game sorted by `(gameNumber, sequence)`; `ensureEditableGame` admits an earlier closed game for Admins; the four edit reducers take an optional `gameNumber` (Admin-only when earlier); the live step view carries `gameNumber`.
- **S7b hand-offs**: `equip_lightcone` requires the character in the caller's draft; `unequip_lightcone` refunds to the light-cone budget, logs `UnequipLightcone`, recomputes and resets confirmations; the auto-resume reads the latest Pause step of the current game (in `join_lobby`'s reconnect branch).

## Findings and deviations

1. **A54 roster clause.** A54 said a concede's roster is the live `LobbyMember` set (the D-75 fallback as the rule). S8d keeps the start-of-draft `MatchResultParticipant` copy for concedes, as for every played match: after A24(2) a tournament lobby parks until the tournament completes, seats are frozen after Waiting (A35) and players may leave the parked lobby, so a live read at job time would drop players who played; under the live rule the fallback objects also carry no account-rating snapshot, so the MMR account modifier would silently drop out. The user approved the deviation on 2026-11-08; A66 amends that one clause of A54 (the rest of A54 stands and is implemented here). A66 also corrects A65(2): the latest-Pause auto-resume lookup lives in `join_lobby`'s reconnect branch, not `client_connected`.
2. The Cancelled cascade reverses S8b: bracket matches, teams, members and assistants are kept (review §5.1), only lobbies are voided. The two S8b tests that encoded the deletion were rewritten under T-S8d.
3. Tournament MMR runs inside `runFinalization` (option `tournamentMmr`) instead of a separate job call, so the only `processMatchMmr` caller is finalization and `MmrHistory` carries the real history id.
4. A65(2) names `client_connected` for the auto-resume lookup; the only such lookup is `join_lobby`'s reconnect branch, fixed there (recorded in A66).
5. Earlier-game Admin edits (A65(4)) record steps and recompute the game and series but do not move the current session budget; the current-game Admin edit still does (asymmetry documented in `docs/match-session/architecture.md`).
6. `admin_restart_tournament_finalize` restarts at cursor 0 rather than the stopped cursor (rolled back with the throw); safe because processed records are deleted.
7. "Nothing to undo in this game." is unreachable: `undo_last_step`'s `turnIndex === 0` check rejects first with "No steps to undo." (both accepted by the test). Polish item for S10.
8. `run_tournament_finalize` has no app-level guard against non-scheduler callers, consistent with the repo's other scheduled reducers; `it.todo` left. The nuke clearing `TournamentFinalizeJob` cannot be tested in-memory (the harness cannot set `STDB_TARGET`); `it.todo`.
9. Three tests set rows directly because no reducer reaches the state (a live lobby stage for the Completed guard, a deleted lobby for the override precondition, a record without a winner for the throwing tick).
10. `create_tournament_lobby` keeps its unused `joinCode` argument (signature stability); `join_lobby` auto-seats in Waiting only.
11. Biome formatting not applied (lint gate is M3).
