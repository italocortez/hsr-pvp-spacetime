## Goal

Remove every series concept from lobbies and the match session (BetweenGames, Shelved, next game, shelve / resume, series settings on lobbies and presets, game numbering inside a match) and make the bracket match the only series: `BracketMatch.bestOf` caps the games, `team1Games` / `team2Games` are derived from the Validated game records plus the A27 head start, the match is decided at `ceil(bestOf / 2)`, one live lobby per match at a time, concede settles the game, stats and MMR per game.

## Decisions implemented

A67(1) stages and reducers removed (also `Finished`, which nothing wrote); A67(2) series settings off `Lobby` / `LobbyPreset` and their reducers; A67(3) no `gameNumber` anywhere inside a match, A65 undone (`MatchResultGame` kept as a one-row-per-record table); A67(4) derived tally and decide / rollback / resolve / override rules in the single writer; A67(5) D-45 "one live lobby per bracket match" with the cap; A67(6) concede = the game; A67(7) MMR per record; A67(8) finalize job unchanged in shape with several records per match. **A69** (user rulings on the step report, 2026-11-08): (1) the head start sits on the bracket row from generation; (2) Admin edits of a closed game end at validation, with precise rejections; (3) the dead code A67 left is removed here instead of handed to S8f. A28's tournament chain and A27's validation untouched.

## Rules as implemented

- **Tally** (`helpers/bracketResults.ts` `matchGames`): team1 = `winnerAdvantage` + Validated records of the match won by Blue (A35: Blue = team1); team2 = Validated records won by Red. Only Validated records count (a concede is Validated, A24(1)). **A69(1):** `bracketStore.insertBracket` writes `team1Games = winnerAdvantage` at generation (group matches 0 / 0), so the stored tally equals the derived one from the first row on; no record represents the head start.
- **Decide** (`recordGameSettled`, called from `handOffToBracket` on validation and concede): a non-Ready match is left alone; the tally is written on every settlement; at `ceil(bestOf / 2)` the match is decided through `applyBracketResult` (routing, A30, SYSTEM actor as before).
- **Rollback** (`rollback_bracket_match`): voids only the deciding record (latest Validated by `settledAt`, id as tie-break) and deletes its lobby, only for matches decided by play; staff / DQ decisions void nothing; the tally is recomputed; a Ready match whose tally already decides is decided again as Played (orchestrator interpretation of A67(4), review #2). **Resolve**: rolls back without voiding and without re-deciding, voids only unsettled lobbies, applies the staff result. **Override** of a tournament record on a Decided match: reverts the bracket decision without voiding (`rollbackBracketResult(…, false, false)`), updates the record (Rejected also voids the lobby), re-decides from the new tally through `recordGameSettled(…, 'Staff')` (review #1, A24 TD-13 / 14). DQ applies the derived tally and rewrites it after the force-concede (review #3).
- **D-45** (`create_tournament_lobby`): rejected when the match is not Ready, when any lobby of the match holds a record that is not Validated ("A lobby for this bracket match is still in play."), when the Validated records already reach `bestOf` ("This bracket match has no games left (best of N).") or when the derived tally already decides ("This bracket match is decided by its games."). The last two are defensive (A69(3): reachable through direct row edits only). A parked lobby with a Validated record does not block.
- **One game**: `start_draft` creates the one session (no head-start seeding); `submitGameResult` (ex `submitSeriesResult`) submits the game at its close; Admin edits move the session budgets (the S8d earlier-game asymmetry is gone); `runFinalization` archives one game.
- **Edit window (A60(7), A69(2))**: `ensureEditableRecord` holds the status rule for every edit reducer: no record → "No pending match result for this lobby."; Pending → editable; Submitted → an Admin may edit (closed game, `recomputeAfterAdminEdit`), anyone else gets "This game is closed."; Validated, Finalized, Disputed, Rejected, Voided → "This game can no longer be edited here; corrections go through override_match_result." for everyone. `ensureOpenGame` only decides 'open' / 'admin' on the game's `closedAt`. `resolveEditWindow` (`postDraft.ts`) keeps its order: Admin + Submitted + closed game → admin window; otherwise the stage guard first, then the status rule.
- **Ordering** without autoinc ids (CLAUDE.md §3 rule 4): the finalize job orders records by bracket order then `createdDate`; the deciding record is the latest Validated by `settledAt`.
- `helpers/seriesSettings.ts` kept minus `resolveAdvantage` (`ensureBestOf`, `ensureWinnerAdvantage` for tournaments, `normalizeLobbyName`). The `select_match_account` D-B-03 ratchet is deleted (A69(3)): the snapshot is taken once at `start_draft` (A66).

## Findings and deviations

1. **Override of a decided bracket match** (review #1): deviation from A67(4) introduced by the brief's wording; fixed, no ruling needed.
2. **Rollback over a tally that already decides** (review #2): A67(4) is silent; the orchestrator chose "the decision is a function of the tally whenever the match is Ready" (re-decide as Played after `rollback_bracket_match`; lobby creation rejects a match decided by its games). Reported to the user, not overruled.
3. **DQ tally** (review #3): written after the force-concede so stored = derived.
4. **Head start not stored before the first game** (T-S8e failing test): the user ruled "a game should be awarded at the bracket level … without adding fake rows" → A69(1): `insertBracket` writes `team1Games = winnerAdvantage`; the test stands as written.
5. **Admin edit window** (T-S8e note): the code admitted Admin edits only on Pending / Submitted records, narrower than A60(7)'s "until finalization"; the user agreed ("admins cannot edit finalized matches", read as: a validated result is final for the editors) → A69(2); the rejections now say why ("This game is closed." / "… corrections go through override_match_result.") instead of "No pending match result for this lobby.".
6. **Dead code** (review #6, T-S8e notes): removed under A69(3); the two defensive D-45 guards stay (reachable through `admin_delete_row`).
7. **Implementer choices in fix pass 2**: `ensureOpenGame` keeps its unused `lobby` parameter (five call sites, smaller diff); `insertGroupBracket` keeps 0 / 0.
