## Deviation from the plan

The plan assumed one `"@module/*": ["./src/*"]` entry. The CLI bundler (Rolldown) matches a `paths` wildcard against a single segment, so `spacetime build` fails with UNRESOLVED_IMPORT on `@module/helpers/tournament/x` (the implementer confirmed with probes; `@shared/bracket/engine` fails the same way, which is why `shared/` folders use barrels, S4). The alias is therefore declared per folder in `tsconfig.base.json` only (33 keys: `@shared/*`, `@bindings/*`, 27 domain folders, `@module/views/*`, `@module/types/*`, `@module/index`, `@module/schema`), inherited by the module and root projects through `extends` (the bundler follows `extends`: `spacetimedb/tsconfig.json` is unchanged from HEAD; the review caught the duplicate block the implementer had added first). `test/tsconfig.json` mirrors the entries relative to `test/` because its own `paths` block (with `@/`) replaces the inherited one. Vitest resolves full paths, so each vitest config has a single `'@module'` alias. A new domain folder needs its entries in `tsconfig.base.json` and `test/tsconfig.json`; a missing entry fails `npm run typecheck` and the build loudly (vitest alone would not notice). Recorded as A72(3).
