# S14.3g: the save animation on the team builder

## Goal

Replace the team builder's save state text with a small save animation beside the loadout's name: a ring that fills, a check, then a floppy disk at rest. Problems keep their words. Nothing about saving itself changes.

## The user's sketch and words

A drawing: a ring filling, an arrow, a check mark, an arrow, a floppy disk icon. "I'm thinking we could do a simple save animation every time we save it, we dont really need the text 'saved in browser' in my opinion, the animation itself should be enough to show that it was saved". And: "we can use this icon for the save floppy" (`tmp/pw/s14-3g/save-floppy.svg`, from SVG Repo). Rulings that still bind: account loadouts save 60 s after the last edit, the wait restarting on each edit, with a 5 minute ceiling; "the donut should turn into a check after"; no "save now" button (A194).

## Choices made here

- **Timings** (tokens): ring completion 300 ms (`--duration-base`, `--ease-out`); breathing only after 700 ms of saving, so a fast save goes from the full ring straight to the check; check: green stroke transition 300 ms, pop 500 ms (`--duration-slow`), tick drawn in 420 ms after 120 ms; hold 1.4 s after the last save (`CHECK_HOLD_MS`); to rest: the ring and tick shrink to 0.6 and fade while the floppy grows from 0.6 (300 ms, 60 ms later).
- **Saving without flicker:** no minimum time; the full ring is what both "saving" and the start of "check" look like, so a save that returns in milliseconds reads as one motion.
- **Coalescing (browser):** a save while the check shows keeps it up without replaying it; it settles 1.4 s after the last save. Typing a name plays one check.
- **Tooltip:** a `title` on the non-focusable, `aria-hidden` box (pointer only). Not focusable for the tooltip's sake: the tooltip guide puts tooltips on controls, and a Tab stop that does nothing would cost keyboard users; they and screen readers get the words from the hidden text, part of the name field's description.
- **Icon normalisation:** the group translation applied to the coordinates (relative commands), `0 0 32 32`, no transform, `currentColor`, `evenodd`.
- **Problem glyph:** a circled "!" in the warning colour (muted for "loading"). "Browser storage is off" moves from a green check to the warning glyph, since nothing is kept past the visit.
- **Dev demo by a hash** (`#save-demo`): the route's search validation drops unknown params before the page reads them; the hash survives. No route file changed.
- **The empty working loadout:** the indicator stays mounted and renders nothing, so the first pick's save still shows its check; one in-between render (a character, not stored yet) shows nothing instead of a warning that flashed for about 23 ms in the first browser run.
