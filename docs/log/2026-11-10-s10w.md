# S10w — a game account in use by a live lobby cannot be edited by anyone (2026-11-10)

## Goal

Implement A142: close the outside edits that could raise an eidolon cost between a bid and its sale (S10u review 2, G2). Also in this log: the independent review of A140 (S10v) and its doc fixes, committed as `b4dbbc7`.

## Decisions implemented

- **A142**: the Admin roster tools are refused while the account is selected in an active lobby, exactly when the owner's own edit is refused (D-24, `accountLobbyLocks`; abandoned memberships skipped). An Admin insert, change or delete of a character, light-cone or synergy cost row is refused while a lobby on that cost set is in Drafting, Equipping or Scoring. The sale fallback of S10u stays for the two routes that cannot be refused.

## Behaviour

| Admin action | Result |
|---|---|
| Add, change or remove a character on an account selected in an active lobby (any stage) | Refused: "This account is selected in active lobby <code>; its roster cannot be edited until the player's membership in that lobby ends or the lobby closes." |
| Insert, change or delete a cost row of a set with a game in Drafting, Equipping or Scoring | Refused |
| The same in Waiting or AwaitingResult, or on another set | Accepted |
| An upsert row equal to the stored row | Skipped: no write, no refusal, audit columns untouched (also outside a live game) |
| A `costSetId` that is not absent or a whole number from 0 to 4294967295 | Refused before any lookup |
| Renaming an account or changing its visibility | Unchanged (allowed, as for the owner) |

## The seed

`scripts/stdb/_seed.ts` sends one call per table, each its own transaction. With games live on set 0: identical prices pass and write nothing; a changed price commits the tables sent before it, is refused at the cost call carrying the change, and the script stops there. Re-running once no game on set 0 is live completes it.

## Review

Independent Fable 5.2 reviewer, read-only, own probes, verdict **COMMIT AFTER FIXES** (`notes/audit-2026-11-09/s10w-review.md`).

- Confirmed: the Admin roster paths are refused exactly when the owner's are, in every stage; the cost guard holds for the three tables including set 0; about 30 edge payloads never changed a price while being treated as identical; only two routes still change owned levels during a round: the deletion or ban of a seated user (any caller) and the roster of a member who abandoned.
- F1 (gating): a non-numeric `costSetId` (`"0"`, `0.4`, `false`, `[0]`, `4294967296`) matched no row and no live lobby, so an insert went into the live set 0. Fixed with `parseCostSetId`; tests per table.
- F2, F3: two false statements (a re-seed refused "as a whole"; "until the player leaves that lobby"). Corrected.
- F4: a test picked its path by list position. Now by name. The six older failures the implementer saw while removing its code did not reproduce; the cause was most likely neighbouring lines removed by hand.
- F5: tests added for Equipping, Scoring and AwaitingResult, for the S10u scenario through the cost tools, and for the two remaining routes end to end.

The fix pass implements the reviewer's stated fixes and was verified by the orchestrator's suite run.

The review of A140 (`notes/audit-2026-11-09/s10v-review-4.md`) returned **SOUND**: the allowed creators are the old set minus plain stand-ins; a stand-in still joins a member-created lobby onto a free seat; no match is stranded. Its three doc findings were fixed in `b4dbbc7`.

## Findings and hand-offs

- The S10u fallback remains for the two routes above; options "owned levels only" were not taken (the user chose to block the edits instead).
- `HsrCharacter` and `HsrLightcone` reference rows (rarity, role, path) stay editable by an Admin during a game: not prices, outside A142.
- A `null` `costSetId` in an `admin_delete_row` key now means set 0 (before: "Row not found").
- A balance patch through the seed cannot change a price while a game on set 0 is live; run it when no draft is in progress or publish a new cost set.
- Not probed by the reviewer: tournament lobbies, the Thirds format, the web bulk-upsert splitter.
- Deviations from a decision row: none.
