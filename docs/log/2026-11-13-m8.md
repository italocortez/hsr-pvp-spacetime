# M8: local preview (2026-11-13)

## Goal

A preview of the built app without a Vercel deploy: `npm run preview` builds against the test database and serves `web/dist` on 127.0.0.1 through the `headers` and `rewrites` of the root `vercel.json`. Test task T-M8. Nothing deployed, no `vercel` CLI call.

## Decisions implemented

A174 (user): every Vercel deploy is treated as production; the preview is a localhost server of the app against test. A50 and A172 rules are what the preview imitates.

## Behaviour

- `npm run preview`: validates `vercel.json`, builds with `VITE_STDB_TARGET=test` forced in the child's environment, checks the bundle targets test, serves on `127.0.0.1:4173`. Flags: `--port` (decimal 1 to 65535), `--no-build`, `--maintenance`. No target flag exists; `--target`, `--prod`, `--env` exit 2.
- The bundle check reads every `.js`, `.mjs`, `.cjs`, `.html` in dist for the inlined `VITE_STDB_TARGET` value; anything but test, or no marker, or an unreadable dist, is a refusal. It runs at start and on every answer that serves the app page (503 until the bundle is test again).
- `--maintenance` answers `/status.json` with `{ "maintenance": true }` from memory; no file changes.
- Files are looked up exact-case, inside dist only; `:`, backslash and NUL are refused; absolute, `//` and backslash request targets answer 400; GET and HEAD only; `/api/*` answers 404 with a note (M5 decides how the login functions run locally). A request error answers 500 and the server stays up.
- Unsupported `vercel.json` syntax (named parameters, `has`, `missing`, `redirects`, `routes`) stops the preview before the build.
- `vite preview` is refused and points to `npm run preview`.

## Deviations and open points

- The implementer ran `npx --no-install vitest --version` once by mistake (nothing installed).

- Not run on Linux or macOS here; CI is the first Linux run of the new tests.
