## The module's Auction rules, as the simulator applies them

1. The character budget pays each sale's winning amount; a bid can never exceed what is left of it (`place_bid`). The winning amount is the E0 cost (the nomination's opening bid, A61(1)) plus what the team bid on top: the builder's per-slot extra bid.
2. The eidolon extra `max(0, cost[e] − cost[e0])` is charged at the sale, character budget first, the rest from the light cone budget (`chargeExtra`).
3. At the end of the draft the leftover character budget rolls into the light cone budget (D-50, `finishDraft`).
4. Light cones are paid from the light cone budget (`equip_lightcone`).
5. The synergy surcharge is not charged; it must fit what is left (`ensureAuctionSurchargeFits`) and counts in the roster cost.

Not modelled: the order of sales (each extra is charged at its own sale in a lobby; A133's no-spill at 0 character budget). Every difference from the mockup's simulator is listed in `pages.md`.

## Deviations and open points

- **The chart's tooltip** is CSS (`:hover`, `:focus-within`) on a focusable column, not `popover="hint"` with `interestfor` as the web-guidance tooltip guide prefers: `interestfor` needs a polyfill in Firefox (no new dependency), and the values are in each column's accessible name already.
- **Number fields** are `type="text"` with `inputmode="decimal"` and hand-made 0.5 steps, not the mockup's `type="number"`, because a controlled number field wipes partial entries such as "2.".
- **No inner scroll** of the cost card in Auction (the mockup has one): the roster card stretches instead.
- **Pairings column only above 0**: chosen over an always-present empty column.
- **Phones:** the chart in full (180px plot), no disclosure.
- **Formatting:** Biome's formatter was run through its stdin mode (prints only, no write flag) on this step's own files, and the output written back by a small script (`fmt.cjs` in the session scratchpad); `RosterSlots.module.css` was among them and its diff holds only this step's lines.
- **A file renamed** with `mv` (`costChart.ts` to `costChartModel.ts`, created in this step: it clashed by case with `CostChart.tsx` on Windows).
- **Invented texts awaiting the user:** every ★ row of the S14.3b wording table in `pages.md` (the explainers rewritten to the module's rules, the over-budget lines, "Back within budget.", "Light Cone", "Bids", "Eidolons", the accessible sentences).
- **The A/B pick** (A190 item 12) awaits the user: `tmp/pw/ab-chart/compare.html`.
- **Not checked:** Firefox, Safari, a real phone, a screen reader; label contrast estimated, not measured with a tool.
- **Files that could go, with the user's word:** `tmp/pw/ab-chart/pairings-__V__-{1440,390}.png` (left by a first run of the A/B script with a placeholder bug).

### Open, with reasons

- **M2** (the tallest column's tooltip can leave the top of the screen): a flip needs measuring on every show; the tooltip is decorative (every value is in the column's name) and scrolling reveals it.
- **M4** (a blank field keeps the old value until it is left): kept on purpose, so clearing a budget to retype it does not flash an over-budget state and an announcement.
- **M6, no Popover API:** every target browser has it (A164); no fallback written.
- **M9** (the eidolon extra drawn inside the character part): the chart shows what each character costs, not which budget pays; the meters show the split.
- **M10** (the roster card stretches beside the tall Auction cost card): a grid layout choice from S14.3a, not part of this fix pass.
- **M12** (three number formatters, "+2.5" for a pair): the sign on a pair modifier is meaningful (pairs can be negative); merging the formatters is a refactor.
- **M13** (`StackedBarChart` carries the team builder's needs): a design note, no defect; revisit when a second page uses it.
- **S7, lightness band:** the light steps (and the AS character) stay above the validator's dark-mode band; a full pass needs hue shifts that leave the mockup's families. The user decides whether AA's move toward coral is acceptable.
- **S6 in the browser:** the Default set has no priced Auction pair, so the pairings wording was checked by tests only.

## Pairings stacked on each bar (A199)

Done in the S14.3c third-review pass (test task T-S14.3c-fix3; the user: "why is the pairing not stacked in the same bar as the mockup tho?" and "we can split the pair evently yeah that's fine").

- The separate Pairings column, its `PAIRINGS_COLUMN` switch and the variant A/B wording are gone (the patch in `tmp/` is left as it is, now obsolete).
- Each active pair puts half its modifier as a "Pairing" segment on top of both its characters' columns; a character in several pairs carries the sum of its halves. Segments add up to the team's surcharge and the columns' totals to the team total (a property test over every team of four from the seed's paired characters, all modes, Classic and Auction).
