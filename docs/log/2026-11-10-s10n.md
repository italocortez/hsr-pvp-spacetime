## Goal

Implement A114 and A116 (lobby creation takes no join code and no preset number) and A115 (match history in pages of 10 with filters, details on demand). A117 to A119 were recorded during this step; A117 and A118 are implemented in S10o.

## Decisions implemented

- **A114**: `create_lobby` and `create_tournament_lobby` take no `joinCode`; the server generates the code; `join_lobby` by code or by id is unchanged.
- **A116**: `create_lobby` takes no `presetId`.

## Schema changes (join the S11 clear-publish list)

`MatchSessionHistory` gains `matchType: MatchType` and `winnerTeamSide: TeamSide` (optional), before the audit columns. `MatchParticipantHistory.by_match_history` is back (S10j had removed it as unused; the detail views read it).

## How the views work

- Optional filters are strings: `''` means any, otherwise the enum tag; an unknown tag matches nothing. `page` starts at 0; a page past the end is empty.
- Order: `playedAt` descending, the id only as a tie-break.
- The list reads the caller's participant rows through the per-user index, the session row of each, the caller's own rating rows, then sorts and slices. No table scan, no other user's rows.
- `matchType` and `winnerTeamSide` are stored on the history row at finalization (the record's match type and final winner), so a concede, a forfeit or a staff decision lists the right winner.
- Detail views return rows only to a caller with a participant row in that match. A coach or a spectator has none and reads nothing.

## Review

Independent Fable 5.2 reviewer, read-only, ran the suites itself, verdict **COMMIT AFTER FIXES** (`scratchpad/s10n-review.md`). Folded in by a fix pass:

- F1 (gating): the list derived the winner from the archived game row, which a concede never updates; a conceded game showed `won: false` to both sides, and a staff decision that flipped the result showed the old winner. Fixed with the sound option: the winner is stored on the history row.
- F2: the match type was derived by two different rules (tournament: the tournament's rating flag; standalone: whether rating rows exist). Now stored; the derivation, the `Tournament` read and the `MmrHistory.match_history_id` index are gone.
- F6: stale mentions of the removed views corrected.
- F9: the hand-inserted coach test replaced by a real one (finalization never writes a coach participant row).

## Findings and hand-offs

- **Confirmed with the user: what an opponent sees after a match** (review F3). The participants view returns every player of a match the caller played in, with user id, display name and the referee / coach / captain flags, anonymous matches included. The removed step view already exposed every acting player's id and name; this adds players who never acted. No rating, game account or other player's rating change is exposed. Consistent with A37 (identities are revealed to a match's players after the match); reported to the user.
- **Cost** (review F4): each list or count evaluation is proportional to the caller's own match count (index rows, session reads, a sort). To be measured at the S11 live run for a player with thousands of matches; how often a view with arguments is re-evaluated is not documented.
- **Frontend rule** (review F5): all argument sets of one view share one client table, so the history page must keep one page and one filter set subscribed at a time (unsubscribe before subscribing the next). For `docs/frontend/` when the page is written.
- Views with arguments are not delivered by `subscribeToAllTables`; the S11 live residue must subscribe them explicitly.
- A tournament match is added to history when the tournament ends but is listed by its played time, so it can appear in the middle of the list.
- `view_my_mmr_history` lost its primary key (views with arguments cannot have one): no `onUpdate` on the client; rows are immutable.
- Finalization refuses a record without a winner (A31), so `winnerTeamSide` is always set by real paths; the optional column covers rows that predate it.
- Test gaps left (review F9): orphan participant rows after an admin deletes a session history row; the rating history's tie-break.
- Deviations from a decision row: none. The stored `matchType` is the record's (copied from the lobby at `start_draft`), the value ratings and stats use.
