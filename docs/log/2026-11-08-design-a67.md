# Design session 2026-11-08 — lobby membership lifecycle review, A66, A67 (one lobby per game)

Orchestrator session (Fable). No module code changed in this session; it produced two decision rows, a review report, the S8d commit and a re-scoped ROADMAP.

## 1. How it started

While the S8d commit waited for the user's ruling on the A54 concede roster, the user asked what "leaving a parked lobby" meant and whether it covered leaving between games of a series. Checking the stages showed that a voluntary Leave in `Shelved` takes `leave_lobby`'s normal path and deletes the `LobbyMember` row, while `join_lobby` admits new joins only in Waiting / Drafting, so a player who pressed Leave in a shelved series had no way back, although `shelve_series` posts "Players may leave and return later." and `resume_series` gates on `voluntarilyLeft`. The user's intent, verbatim: *"technically if you 'leave' a match that was shelved, you could come back later."* They asked for "an extra pair of eyes to see all the inconsistencies" and to think "on what a user would click on the UI and what would fire off in the backend depending on the scenario".

## 2. The review

Independent **Fable** reviewer, read-only, brief `prompt-lobby-lifecycle-review.md` (scratchpad); the mockups predate series and shelving, so the reviewer was told to derive the missing controls from the contracts instead of listing their absence. Report copied verbatim to `docs/log/2026-11-08-lobby-lifecycle-review.md` (scenario matrix 7 stages × 14 actions with `file:line`, 14 ranked findings, a recommended model with 11 backend changes and a 14-row UI control table, 7 open questions). The orchestrator spot-checked nine evidence lines; all hold.

## 3. Recommendation and decision

Orchestrator's recommendation: drop Shelved only (it carried findings 1, 4, 5, 13 and the resume gate), make BetweenGames an ordinary live stage ("once the draft starts you are in until the result"), keep `bestOf` {1, 3} as the game cap, fix the stage-independent findings in a small S8e. The user judged the series machinery over-engineered as a whole and decided **one lobby per game**: *"I still feel like a new lobby per game is the best option personally, this is my decision, even if we have to scope again things that we did and need a rewrite for it."* The orchestrator's dissent (BetweenGames would have kept the Bo3 room at near-zero code cost; ten of the fourteen findings are stage-independent and remain) is recorded in A67's Why.

Blast radius measured before the decision (module files outside tests / test files / doc files): `gameNumber` 24 / 16 / 7, `bestOf` 16 / 11 / 11, `MatchResultGame` 15 / 8 / 9, `BetweenGames` 14 / 8 / 9, `currentGameNumber` 13 / 5 / 2, `bestOfNAdvantage` 11 / 3 / 7, `winnerAdvantage` 9 / 22 / 4 (mostly the shared bracket engine, which keeps it), `refereeControlsShelving` 8 / 7 / 4, `Shelved` 7 / 1 / 5. Eight tables lose columns, three change primary keys, three reducers are deleted.

## 5. A67 in short

A lobby hosts one game (Waiting → Drafting → Equipping → Scoring → AwaitingResult); BetweenGames, Shelved and the unused Finished stage go, with `advance_to_next_game`, `shelve_series`, `resume_series`; no series settings on lobbies or presets; no `gameNumber` anywhere inside a match (A65 superseded entirely); the bracket match is the only series: `BracketMatch.bestOf` caps the games and `team1Games` / `team2Games` are derived by the single writer from the Validated records plus the A27 head start, decided at ceil(bestOf / 2); `create_tournament_lobby` rejects decided or capped matches; concede settles the game; stats and MMR per game; the finalize job is unchanged in shape. Supersedes A65, parts of A27, A28, A56, A60, the S6 series settings and contract rules D-10, D-15, D-16, D-19, D-93. Full text: `DECISIONS.md` A67.
