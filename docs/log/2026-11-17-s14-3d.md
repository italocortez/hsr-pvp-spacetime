# S14.3d: the team builder's screenshot export (2026-11-17)

## Goal

Fourth sub-step of the team builder: export the team as a picture, drawn with our own code from the team's data (Canvas 2D API, no library, no DOM capture), with "Copy image" and "Download" and the old tool's "Hide Team" intent; plus one leftover fix in `readAmount`. Test task T-S14.3d. No backend change, no subscription, no network call to the database, nothing stored, no dependency, nothing deployed.

## Decisions implemented

- **A190 item 8:** the screenshot export from the old apps.
- **A202 item 2:** our own code, without an external library (the old site used `html-to-image`).

## Choices made here (for the user to rule on)

1. The picture is 1200 by 675 (16:9), drawn at device pixel ratio 2, PNG; laid out as the page's slots with captions, the pairings and, in Auction, the two budgets.
2. The note is never drawn and not offered as an option.
3. "Hide who is on the team" hides names, portraits, element and path icons, light cone names and art, and the names in the pairings; it keeps costs, levels, bids, budgets, the total and the loadout's name, and marks the picture "TEAM HIDDEN". Changed after review by the user's ruling: the hidden picture drops the loadout name ("Hidden team", `team-hidden.png`).
4. The controls sit in the Loadouts card under "Copy link", as a second row of two buttons with the option and a status line under them; no "Share" menu (two per row fit at 360).
5. File name `team-<loadout name>.png` (rule in `pages.md`).
6. `readAmount`: a comma followed by exactly three digits is refused as unclear whatever stands before it, so ",500" is refused like "0,500" (the existing test pins "0,000" as refused, so "both read 0.5" was not open).
