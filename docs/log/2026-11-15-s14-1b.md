# S14.1b: the phone menu (2026-11-15)

## Goal

Replace the bar's sideways-scrolling item row at phone widths (560px and below, `--bp-sm`) with a compact menu button, the current page's name beside it, and a panel under the bar. Above 560px the bar is unchanged.

## Decisions implemented

- User, 2026-11-15: variant B2 of the A/B prototype (`tmp/pw/ab-menu/`: A the scrolling row, B1 a labelled button, B2 a compact icon button). "I like how B2 was implemented, we can use that." The prototype's A/B switch and the B1 variant are not shipped.
- Pattern: a disclosure (button with `aria-expanded` and `aria-controls` revealing a list of router links), per the navbar guide; not an application menu.

## What exists

- `web/src/shell/PhoneMenu.tsx` (new): `PhoneMenu`, `useMenuForm`, `NAV_MENU_QUERY` (read from `--nav-menu` in `styles/media.css`), `useFocusHandover`, `currentItem`.
- `web/src/styles/media.css`: `@custom-media --nav-menu (max-width: 560px);`, the one line that moves the switch point. `web/vitest.config.ts`: `media.css` processed in tests (else its `?raw` import is an empty string).
- `web/src/components/MenuIcon/MenuIcon.tsx` (new): the one copy of the menu glyph.
- `web/src/shell/NavBar.tsx`: one `nav` ("Primary") at every width; the items row moved into `ItemRow` and rendered above 560px only; the menu at 560px and below; the gear above 560px only; `onMenuInset` passes the open panel's height up.
- `web/src/shell/NavBar.module.css`: the phone rules (button, page name, panel); the row's phone-only rules removed (chevron 16px width and margins, item `8px 14px 8px 18px` padding).
- `web/src/shell/AppShell.tsx`, `ConnectionBanner.tsx`, `ConnectionBanner.module.css`: the reconnecting line moves below an open panel.
- `web/src/shell/PhoneMenu.test.tsx` (new, T-PHONEMENU): 41 tests.
- `docs/frontend/pages.md`, Shell (S14.1): "Items row (above 560px)" and "Phone widths" replace "Narrow screens" and the old "Phone widths"; Bar, Files, mockup comparison, known limits, screenshots updated.

Full behaviour, keyboard table and measurements: `docs/frontend/pages.md`, Shell (S14.1), Phone widths.

## Deviations and open points

- The form is chosen in script (`matchMedia` through `useSyncExternalStore`) rather than CSS alone, so only one of the row and the menu is in the DOM (one landmark, nothing hidden to focus). The query is parsed from `--nav-menu` in `media.css` at load (`?raw`), so there is one source; it costs about 2.5kB (1kB gzip) of entry chunk for the file's text.

## Last pass (orchestrator, after the independent review)

1. Focus handover when the bar switches form (narrowing: the Menu button; growing: the current row link, else the first).
2. A focused panel row removed while open (lost role): focus to the Menu button.
3. The list keeps 8px of bottom room for the underline mark: no inner scroll at 100, 150, 200% root text when the panel fits (Edge, 390, admin: 300/300, 300/300, 342/342).
4. The switch point is `--nav-menu` in `media.css`; the panel's label column comes from the bar's variables. Moved to 1040 and back as a proof (591 web tests passed at 1040; shots in `tmp/pw/s14-1b/switch-1040/`).
5. Test gaps closed (search-only navigation closes; modified click; links only while open; listeners removed; sub-path rule; Escape with focus outside). `shell.test.tsx`: one describe title renamed, no expectation changed.
6. The current page's link with another search goes to the bare path in the panel as in the row (both drop the search); focus returns to the Menu button.
