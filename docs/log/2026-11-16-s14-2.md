# S14.2: the costs page (2026-11-16)

## Goal

Port the cost tables page (`/costs`) from the frozen mockup onto real data: characters and light cones, both draft modes, the three game modes, the default cost set and published custom sets, filters, search, sort and synergies, with every view setting in the address. Then, after the user tried A/B prototypes, ship the collapsing phone name column, the archetype filter and a one-line element row (S14.2b). Test tasks T-COSTS and T-COSTS-B. No backend change, nothing deployed.

## Decisions implemented

A13 (one responsive tree), A49 and A49a (CSS Modules, tokens, the breakpoint scale: the mockup's 720 px snapped to 768), A60, A77, A108, A166 to A173 (the frontend rules, the address as plain text A169), A183 and A184 (images through `RemoteImage` and the cache worker). User rulings of 2026-11-16 in the brief: cost sets (Default plus published sets, "Cost Set" label, a custom set fixes the game mode), data loading (the default set in the reference set, a custom set as a route subscription, disjoint queries, client filtering by `costSetId`), synergies (both characters, per draft mode, zeros hidden, a real minus sign), the 3★ light cones (`--lc-3star`), the address keys, joke aliases searchable. User decisions after the A/B prototypes (2026-11-16): the phone name column "B3" ("This version works"), the archetype filter, the element chips in one row on phones; and the scroll-linked collapse kept as a reusable pattern.

## What exists

- `/costs` inside the shell: the intro with its hide control (one `h1` in both states), the control bar (Table tabs, Draft Mode, Game Mode, Cost Set), the table card (count, filter row, the sortable table in its own scroller, the footer line), loading, error with Retry, the unknown-set notice, the empty state.
- The address: `tab`, `draft`, `mode`, `set`, `el`, `path`, `role`, `rarity`, `arch`, `q`, `sort`, `dir`, validated and canonical; typing replaces the history entry, every other control pushes one.
- Data: the reference set gained the default cost set's three queries (`cost_set_id = 0`); a custom set is a route subscription on `= N`; the archetype filter reads the archetype tables already in the reference set.
- Shared components: `SegmentedControl` (+ `ControlSelect`), `FilterChips` (with a `fit` layout), `RarityBadge`, `SearchField`, `MultiSelectDropdown`; `RemoteImage` gained a failed-load box sized by the caller's class; `styles/visuallyHidden.module.css`; `lib/scrollCollapse.ts` with `styles/scrollCollapse.module.css` (the scroll-linked collapse, documented as a pattern in `component-hygiene.md`).
- Phones (560 px and below): the name column is sticky and collapses with the sideways scroll to the expander slot and the portrait, the name fading under the moving edge; the seven element chips share one line down to 320 px.
- Accessibility: row headers named by the name alone; synergy values tied to the character, the partner and "Extra Cost"; the dropdown as a disclosure of native checkboxes; keyboard focus reopens a collapsed cell.

## Deviations and open points

- The brief asked to remove a `STICKY_VARIANT` constant and a B2a branch; neither was in the tree (the B3 patch had dropped them); the prototype's naming and its `:has()` focus rule were replaced.
- The value copy in a collapsed synergy row is drawn by CSS (`content: attr(data-value) / ""`), not a DOM node, so the value is in the DOM once.
- The scroll-linked collapse writes from the `scroll` listener itself in its script path (scroll events fire once per rendered frame); a `requestAnimationFrame` hop measured worse.
- `arch` holds archetype names, not ids (stable, readable, the same on test and prod).
- Open: (the empty state on phones and the dropdown covering the bar were fixed in the last pass) the wording marked "implementer's wording, awaiting the user" in `pages.md`; `docs/cost-tables/contract.md` does not exist yet (entries proposed in the hand-back).
- Not checked: Firefox, Safari, a real touch device, a screen reader.
- Remote image traffic in S14.2b's browser work: roughly 700 to 800 UploadThing image requests, first screens only (the final screenshot run 284; three earlier runs of the same script stopped on a test-harness fault after their first nine views, about 400 more; about 75 in two checks and one plain page load).
