# S10l — signing in to an existing account keeps the guest's tournament entry (2026-11-10)

## Goal

Implement A112: when a guest signs in with a provider account that already has a user, the guest's tournament entries move to that user before the guest is deleted.

## Decisions implemented

- **A112**: in `server_link_provider`, the path that re-points the identity to an existing user and deletes the guest first moves each of the guest's entries in an unfinished tournament (enrolment, team membership and captaincy, the guest's own team requests); locks are rebuilt from the existing user's game accounts; an entry the existing user cannot hold is settled as a deletion (A94(2)).

## Files changed

- Module: new `helpers/tournament/entryTransfer.ts` (`moveTournamentTiesToUser`, `canHoldEntry`, `meetsMinimumMmr`, `moveEntry`); `reducers/identity/server.ts` (one call before `performUserDeletion`).
- Tests: new `s10l-link-keeps-entry.test.ts` (20).
- Docs: architecture and contract files per the checklist below.

## Schema changes

None.

## The rule as built

- **Moved**: the enrolment re-keyed with its status (a Disqualified entry included), alias and `createdDate` (registration order); the membership; the captaincy (also when the guest has no membership row left); the guest's own team requests; a solo team renamed by `soloTeamName` in a non-anonymous tournament. Bracket rows hold team ids and are untouched.
- **Locks**: the guest's `TournamentPlayerAccount` and `TournamentWaitlistAccount` rows are deleted; a non-waitlisted, non-disqualified entry gets locks on all of the existing user's game accounts; a waitlisted entry carries none, so promotion locks all.
- **Not moved** (left to the deletion's settlement): the existing user already has an enrolment or a membership in that tournament; the tournament requires a roster and the existing user has no active game account; the existing user is below the tournament's minimum rating (active season, initial rating when no row).
- The existing user's stand-in approvals for matches the new team plays are deleted, so they cannot sit on both sides.
- No tournament-change allowance is consumed; the audit actor is the system user, as in the rest of the link path.

## Review

Independent Fable 5.2 reviewer, read-only, ran the suites itself, verdict **COMMIT AFTER FIXES** (`scratchpad/s10l-review.md`). No takeover, capacity or ban-evasion path; moving a Disqualified entry is the stricter and sound choice; no re-key can collide. Folded in by a fix pass:

- F1 (gating): the minimum-rating floor was not applied to the existing user, on the false premise that a floor tournament cannot contain a guest (an organizer can set the floor, `requireVerified` and `requireRoster` after guests enrolled).
- F2: the existing user could hold a stand-in approval for the opposing team of the same match.
- F7: a disqualified guest's emptied team kept the deleted guest as captain.

## Findings and hand-offs

- **Games already played stay with the guest id** (review F5): participant rows, steps and referee fields are not rewritten. The bracket credits the right team; stats, achievements and rating for those games go to the archived guest, not to the existing user. Reported to the user.
- **A game in progress at sign-in is lost for that seat** (review F4, within A112(4)): the guest's row becomes away and abandoned and the signed-in user cannot take the seat mid-game; a solo side becomes forfeit-eligible. The entry survives for the next game.
- **A guest entry is claimed by whichever account signs in on that session** (review answer 6): by design, and it lets a player who missed registration take over a registered guest session. Reported to the user.
- Calendar auto-invites do not follow (review F6); a seed computed from rating before the sign-in is not recomputed (review F8).
- **Late locking after the move** (review F3): `hasPlayedTournamentGame` is false for the existing user because played rows keep the guest id, so they can add an account created after sign-in until their own first game. Kept: it is the way out for a user who had no game account.
- `server_link_provider` is guarded by the server identity only; the guarantee about its arguments rests on the auth function of M5.
- The rating test is duplicated from `ensureMinimumMmr` (private to the registration reducer file); a later pass can share it.
- Untested parts of A112 (review answer 7): CheckIn and checked-in entries, Seeding before generation, a guest with a second identity left, played games through finalization, a guest seated in a lobby at sign-in.
- A guest can be made a tournament assistant (`assign_tournament_assistant` does not reject guests); the row is deleted with the guest.
- Deviations from a decision row: none.
