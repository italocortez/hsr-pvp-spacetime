# M6: connection, subscription layer, dev egress meter (2026-11-13)

## Goal

The app in `web/` connects to SpacetimeDB (test target in dev), feeds the auth store from `view_my_profile`, offers a route-subscription hook and a session-long reference set, shows offline and maintenance splashes, and has a dev-only egress meter. Test task T-M6.

## Decisions implemented

A44(1) and PAGE-MAP D10 (Layer 0 is `view_my_profile` and `view_my_lobbies` only), A77 (no page reads `User`), upgrade report R5 (keep handles, unsubscribe on cleanup), A166, A170. Orchestrator's choices, told to the user: the wording of the two connection splashes; `withConfirmedReads(false)`; no cost-table subscription until the user rules on what the "active" cost set is.

## Behaviour

- Auth store starts at not ready; visitor after the first empty result; user after a row; follows later inserts, updates and deletes; keeps the snapshot while reconnecting; not ready on failure.
- `failed` comes from: a failed first connection, a Layer 0 subscription error, a disconnect the SDK starts itself, a refused stored token (401 or 403: the token is deleted and Retry reloads the page).
- A mid-session drop reconnects inside the SDK without limit; the page stays as it is (a banner belongs to the app shell step).

## Review (Fable 5.2, read-only)

No blocker. Three should-fix items on error paths, fixed: Layer 0 subscription error left auth not ready forever; an SDK-started disconnect was read as closed by the app; a refused stored token locked the client on the splash. Minor fixes: no repeated auth republish under the splash, a safe key for the query list, no empty flash of the reference set on a connection swap, an error state for the reference set, more tests (27 mutation probes: 25 caught, the 2 survivors covered now), the meter's header comment and its per-second work. A second independent review of the fix pass follows this commit.

## Open questions with the user

1. Maintenance: the server drops a refused socket without a reason, so the visitor sees the offline splash and the SDK manager keeps rebuilding (up to two attempts a minute per open tab). Options: keep; a static status file at M7; accept the socket and expose a flag (reverses B-8).
2. Bundle: the SDK and the generated bindings add about 56 kB gzip to the first download; lazy-loading the connection after first paint is possible.
3. A guard that refuses dev mode with the prod target.
4. Cost tables: the module has no single active cost set.
