# S14.3-pairs: no negative pair modifier in a cost set

Date: 2026-11-17. Nothing published; no maincloud call.

## Goal

A cost set's synergy pair modifier is always 0 or more. The module refuses a negative one wherever a cost set's pair
modifiers are written, and the seed tooling refuses one before anything is sent.

## Decision implemented

DECISIONS.md A199(2) (user, 2026-11-17: "a cost set should not allow negative pairings, that breaks many things, so lets
assume its always 0 or more"). A199(3): the floor at 0 in the scoring code stays as a safeguard. It supersedes the S10f
rule (roster audit #9) that allowed a modifier within ±100000 ("negative modifiers stay allowed").

## Paths checked

| Path | Check | Why |
|---|---|---|
| `edit_draft_synergy_cost` | yes | writes the draft row |
| `create_cost_set` (copy of the source's live synergy rows) | yes, refuses (no clamp) | a clamp would change a price silently; the source's owner can fix the row and publish |
| `publish_cost_set` | yes, every draft synergy row | the only path to the live rows of a custom set (`mirrorDraftToLive`) |
| `admin_bulk_upsert('HsrSynergyCost')` | yes, each incoming value | the seed (`_seed.ts`) and the Admin bulk editor write set 0 and any set through it |
| `ensureDraftCopy` | no | runs inside an edit or a publish; a negative row it copies is replaced by the edit or refused by the publish; a check there would leave the owner unable to fix the row |
| `mirrorDraftToLive` | no | called only by `publish_cost_set`, after the check |
| `fillMissingAtZero` | no | character and light-cone rows only |
| `admin_delete_row`, `deleteCostSetRows`, `server_nuke_test_data` | no | delete only |
| `server.ts` seed | none exists | the server has no reference-data upsert of its own; the seed goes through `admin_bulk_upsert` |

No other module code writes `HsrSynergyCost` or `CostSetDraftSynergy` (grep over `reducers/` and `helpers/`).

## Existing data

`data/seed/synergies.json`: 60 modifiers, none negative (also asserted by a test). A negative row already in a database
stays until it is edited; no migration. Prod holds none; test1's data is disposable. Such a row refuses a copy of its
set and a publish of its draft until the pair is edited to 0 or more. The scoring floor (`lineupCosts` in
`helpers/results/scoringHelpers.ts`, and `shared/teambuilder`) still protects. `shared/scoring` and `shared/teambuilder`
were not changed: no comment there says negative modifiers are allowed (the teambuilder floor tests build negative
pairs directly and stay).

## Tests (T-S14.3-pairs)

New, `pair-modifier-floor.test.ts`:
- edit: a negative modifier is refused with the text and writes nothing; 0 and a positive one are stored
- edit: editing a stored pair to a negative value is refused and the stored value stays
- create: a source row with a negative modifier refuses the copy; no set and no draft row is created
- create: source rows at 0 and above are copied as they are
- publish: a negative draft row refuses the publish; the set stays a draft, no live row; fixed, it publishes
- publish: a published set (no draft) with a negative live row is refused until the pair is edited
- bulk upsert: a negative insert refuses the whole call; 0 and a positive one are written
- bulk upsert: updating a stored row to a negative value is refused and the stored value stays; null keeps it
- seed: `normalizePairings` throws a plain error naming the pair
- seed: `data/seed/synergies.json` normalizes with every modifier 0 or more

Negative rows "written before the rule" are inserted directly into `HsrSynergyCost` / `CostSetDraftSynergy`, as the
scoring fixtures do (no reducer can write them any more). The seed normalizer tests sit in the module suite like
`seed-rows.test.ts` (which already imports `seed-normalizers`); `scripts/` has no test folder of its own.

Changed assertions:
- `cost-input-rules.test.ts`, "synergy modifier ...": the range text is now "between 0 and 100000"; `-Infinity` and
  `-100001` now get "A pairing's cost cannot be negative."; the accepted low end `-100000` became `0`.
- `cost-set-reducers.test.ts`, "a synergy edit is keyed by the 5-tuple ...": the Auction re-edit value `-1.5` became
  `1.5` (the test is about the upsert key, not the sign).
