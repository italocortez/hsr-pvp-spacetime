## API (the contract S8b–S8d build on)

- `shared/bracket`: `generateSingleElim`, `generateDoubleElim`, `classifyMatches`, `BracketEngine`, `checkStructure`, `toRowDrafts`, `foldSeeding`, `nextPowerOf2`, keys (`wbKey`, `lbKey`, `GF_KEY`, `TP_KEY`, `groupKey`); `groupCount`, `splitIntoGroups`, `roundRobin`, `groupSpec`, `meetingRound`, `placeQualifiers`; `rankGroup`, `compareGroupTeams(a, b, matches, all)`, `groupTeamStats`; `isEligibleTeam(team, members, settings)`, `allowsThirdPlace`, `canOpenRegistration`, `canCloseRegistration`, `canStartInProgress`, `canComplete`, all returning `GuardResult` (`{ ok: true } | { ok: false, reason }`).
- `applyBracketResult(ctx, bracketMatchId, winnerTeamId, decidedBy, games, actorId)` is the only writer of `BracketMatch.winnerTeamId` (besides `settle`, which stamps structural walkovers, and `rollbackBracketResult`, which clears it): Ready → Decided; the same winner again is a no-op; a different winner on a Decided match throws "roll back first"; routes the winner and the loser to their exact slots; a loser without a loser route becomes `Eliminated` (only from `Active`, never for group matches).
- `rollbackBracketResult(ctx, bracketMatchId, actorId)`: refuses when anything downstream is Decided; unwinds downstream walkovers recursively; games 0-0, state Ready, `Eliminated → Active`.
- `allowedSlotsFor(ctx, lobby, userId)`: team1 → Blue player / coach, team2 → Red player / coach, approved stand-ins by `teamId`, everyone else Spectator (always allowed); every slot for a non-tournament lobby.

## Interpretations (implementer, Opus; accepted by the reviewer)

- `placeQualifiers`: the brief's literal "runners-up in reverse group order" pairs each runner-up with its own group winner under fold seeding when the block fills the bracket (2 groups × 2 qualifiers). Implemented instead: seeds handed out rank by rank, group winners take seeds 1..G in group order, later ranks alternate direction and each team takes the free seed of its rank's block that delays meeting its own group most. The property (no same-group round-1 pairing; a better rank always gets a better seed) is tested for 2–16 groups × 1–3 qualifiers and was re-swept by the reviewer.
- `isEligibleTeam` takes the member rows (an undefined entry = not enrolled); `canCloseRegistration` covers both entries into Seeding (from Registration when check-in is off, from CheckIn otherwise); `canComplete` cannot see that a group-into-elimination tournament has no elimination rows yet (documented; S8d checks the format first).
- `settle` writes `winnerTeamId` for walkovers; `deleteBracket(ctx, tournamentId, actorId?)` also cascades the calendar rows of the matches and keeps `seedNumber`; group match numbers count within (group, round); `groupStandings` lists every team of the group regardless of status.
- A structural walkover fed by an unplayed match stays Pending with one BYE slot until that match is played; the walkover is stamped once the real entrant is known (T-S8a asserts this).
- Three-team single elimination with a third-place match: the third-place match is a walkover, so one team is eliminated.

## Findings and deviations

1. The prototype's elimination engine moved without behaviour change; everything group-related (sizing, round robin, qualifier placement, ranking) is new pure code ported from the legacy helper with the A32 `floor` fix and the A30 order.
2. The qualifier placement rule in the brief was wrong and the implementer proved it with a counter-example; the implemented rule is property-tested rather than pinned to a literal order.
3. `applyBracketResult` is exported but not yet called: the legacy advancement paths still write `winnerTeamId` until S8c deletes them.
4. The implementer ran a throwaway simulation (2–16 teams, both formats, random rollback and re-apply) in its scratchpad; nothing of it is in the repo.
5. The reviewer could not run `npm run stdb:generate` in its sandbox (the auto-mode classifier blocked the bindings write); the orchestrator's churn check covers it.
6. Biome formatting not applied (lint gate is M3).
